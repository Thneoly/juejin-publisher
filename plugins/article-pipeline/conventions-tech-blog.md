# 体例纪律（技术博客版：掘金/知乎平台文风基线，用户实战贡献）

## 语言与语气
- 简体中文正文；技术名词、命令、字段名保留英文
- 口语化但专业——"技术人在茶水间聊天"，不是论文也不是官方文档
- 可以适度用技术梗和自嘲，但不要硬凹表情包

## 结构纪律
- 标题必须有钩子（悬念/数字/反直觉），不超过 30 字
- 开头 3 行内建立悬念或痛点——读者 3 秒决定关不关
- 每段不超过 150 字（手机屏幕一屏三段）
- 大段纯文字（>300 字）必须用表格/列表/代码块打断
- 结尾必须有"现在就能做的事"（验证命令/收藏/30 秒自检）

## 代码纪律
- 所有代码块标语言（```bash/```yaml/```text）
- 命令可直接复制执行；不可执行的标注原因
- 输出示例用注释或纯文本块展示
- 版本敏感处标注"以官方文档为准"

## 事实纪律
- 每个技术断言要么有把握，要么标注"需要核验"
- 引用数据/版本号必须可靠；不确定的降级为"大约/经验值"
- 预埋至少一个反方观点并回应（评论区一定有人反驳）

## 引流纪律
- 文末引流提到 GitHub 仓库/书站时自然带过，不硬广
- 不在正文中插入推广链接（掘金机审会驳回）
- 薪资数字慎用（掘金机审对"招聘语汇×钱数"敏感）

## 禁止事项
- 占位符（TODO/待补充/XXX）
- 成堆 emoji
- "大家好"式开场
- 超过 500 字的段落
- 未标注语言的代码块
- 硬广/招聘推广内容
