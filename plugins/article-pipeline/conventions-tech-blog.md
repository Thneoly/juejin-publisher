# 体例纪律（技术博客版：掘金/知乎平台文风基线，用户实战贡献）

## 语言与语气
- 简体中文正文；技术名词、命令、字段名保留英文
- 口语化但专业——"技术人在茶水间聊天"，不是论文也不是官方文档
- 可以适度用技术梗和自嘲，但不要硬凹表情包

## 结构纪律
- 标题必须有钩子（甜蜜点 15~25 字位，上限 30，英文按字符宽折算；超 40 仅限故事型且摘要前 2 行补钩）
- 标题公式优先级：数字清单型 ≈ 反直觉疑问型 > 故事型 > 对比型（四大被验证模板：①否定祈使「别再裸用X了」②数字+收益动词「N个亲测X，效率拉满」③趋势疑问「为什么越来越多人放弃X」④亲历迁移「用了X大半个月，真实感受」）
- 标题必须含至少 1 个具体英文产品/协议名（品牌词>类别词，禁用「大模型/AI技术」替品牌词）
- 标题含至少 1 个具体数字，优先清单数量词（N个/N款/N条），百分比不用，钱数禁入标题（机审红线）
- 首段第一句必须是判断或转折句（第一人称+情绪化结论或先扬后抑），禁背景铺垫开场——读者 3 秒决定去留
- 每段不超过 150 字（手机屏幕一屏三段）
- 大段纯文字（>300 字）必须用表格/列表/代码块打断
- 结尾必须有"现在就能做的事"（验证命令/收藏/30 秒自检）

## 代码纪律
- 所有代码块标语言（```bash/```yaml/```text）
- 命令可直接复制执行；不可执行的标注原因
- 输出示例用注释或纯文本块展示
- 版本敏感处标注"以官方文档为准"

## 事实纪律
- 每个技术断言要么有把握，要么标注"需要核验"
- 引用数据/版本号必须可靠；不确定的降级为"大约/经验值"
- 预埋至少一个反方观点并回应（评论区一定有人反驳）

## 引流纪律
- 文末引流提到 GitHub 仓库/书站时自然带过，不硬广
- 不在正文中插入推广链接（掘金机审会驳回）
- 薪资数字慎用（掘金机审对"招聘语汇×钱数"敏感）

## 禁止事项
- 占位符（TODO/待补充/XXX）
- 成堆 emoji（emoji ≤1 个或不用；感叹号频次 ≤15%，优先用反问句制造口语感）
- "大家好"式开场
- 超过 500 字的段落
- 未标注语言的代码块
- 硬广/招聘推广内容

## 选题规则（2026-09 热榜数据）
- 上热榜的标题必须落到具体工具名（Claude Code/DeepSeek/MCP 级别）或 Agent 关键词
- K8s/云原生系列发布前标题过桥接检查：「这和 AI 有什么关系？」——答案要能体现在标题或摘要里
- 发布排期：主力长文周一（热榜 30% 是周一发）、次选周四；周六不排；at 默认工作日 09:15-10:30 或 14:00-15:00
- 新品热点双窗口：0-1 天发当天快评（轻量线，跳过对抗复审），3-7 天发生态盘点（完整线）
- 系列标记是留存不是获客：标题/摘要不得依赖前篇知识，新读者零门槛
